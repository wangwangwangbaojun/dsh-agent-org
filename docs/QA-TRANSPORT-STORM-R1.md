## 缺陷卡 DEF-TRANSPORT-STORM-1
- **症状**：dsh CLI 瞬断（stderr=`dsh: TRANSPORT: Connection error.`）使角色进程 exit 1；org-role.js:192 空 stdout 兜底将其转为「[任务失败 X]」回投邮件，邮件作为新任务唤醒对端 daemon；故障窗口内反馈增益≥1，573 封/140 分钟，其中≈100% 为无信息量纯通知，挤占真实工作队列（node-4 积压 25 件中 23 件为噪声）。
- **根因分层**：①外部触发=宿主 dsh 传输层瞬断（非本插件代码，运维面观察项）；②**本插件缺陷=崩溃→回投链路零阻尼**（无退避重试、无按根任务 id 去重、无链深闸、纯失败通知收件无默认终态）。
- **归属**：②归 后端工程师（node-2，bin/org-role.js 线）；①由 负责人 汇总知会运维/人工。
- **修复建议（非裁定）**：a) TRANSPORT 类崩溃先本地指数退避重试 N 次再回投；b) 通知内容本身是「[任务失败…]」时链深封顶 1，二次失败不再回投只写 reports.jsonl；c) daemon 对纯失败通知收件默认走 `[系统确认]` 零回投语义，仅当任务 id 挂有未完成实质请求才唤醒。
- **回归口径（修复后）**：重放 TC1 分桶脚本，新增纯失败通知在注入瞬断场景下 ≤1×根任务数；TC2 链条在第 2 跳内终止；真实工作件在故障窗口的送达率不受抑制。
